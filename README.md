# Osaka Trip 2027

หน้าเว็บสำหรับเตรียมทริปโอซาก้า: นับถอยหลังถึงเครื่องออก, การ์ดไฟลท์บิน และตัวช่วยเลือกโรงแรม
(ค้นหา กรอง เรียง เปรียบเทียบ ส่งสรุปเข้า LINE และเพิ่ม/ลบที่พักร่วมกันหลายคนได้)

เป็นเว็บสถิต (HTML + JavaScript ล้วน) ไม่ต้องติดตั้งอะไร ไม่มีเซิร์ฟเวอร์ของเราเอง (ใช้ Firebase เก็บที่พักที่เพิ่ม/ลบ)

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บและสไตล์ |
| `app.js` | ตรรกะทั้งหมด (นับถอยหลัง, การ์ดไฟลท์, ระบบโรงแรม) |
| `hotels.js` | **ข้อมูล** ไฟลท์บินและรายชื่อโรงแรม (ไฟล์ที่คุณจะแก้บ่อยที่สุด) |
| `style.js` | แท็บแนะนำสีเสื้อผ้า |
| `couple-pixel.png` | รูปคู่สไตล์ pixel art ที่หัวหน้าแรก (ขนาดจริง 57×68 px ใช้ขยาย 2 เท่า) ต้องอัปโหลดคู่กับ `index.html` |
| `couple-pixel-big.png` | ไฟล์เดียวกันขยาย 10 เท่า พื้นหลังโปร่งใส สำหรับเอาไปใช้ที่อื่น (ตัวเว็บไม่ได้ใช้) |

## เปิดใช้งานบนเครื่อง

ดับเบิลคลิก `index.html` ได้เลย หรือรันเซิร์ฟเวอร์ชั่วคราว:

```bash
python3 -m http.server 8000
# เปิด http://localhost:8000
```

## ขึ้น GitHub Pages

1. สร้าง repository ใหม่ แล้วอัปโหลดไฟล์หลัก 4 ไฟล์ (`index.html`, `app.js`, `hotels.js`, `style.js`) หรือ `git push` (ขาดไฟล์ใดไฟล์หนึ่งแล้วบางแท็บจะใช้ไม่ได้)
2. ไปที่ **Settings → Pages**
3. Source เลือก **Deploy from a branch** แล้วเลือก branch `main` โฟลเดอร์ `/ (root)` กด Save
4. รอ 1-2 นาที เว็บจะอยู่ที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

## เพิ่ม / แก้ / ลบที่พัก (ฐานข้อมูลกลาง Firebase)

ที่พักทั้งหมดซิงค์ผ่าน Firebase Realtime Database ทุกคนที่เปิดลิงก์เดียวกันเห็นข้อมูลตรงกัน (อัปเดตอัตโนมัติทุก 20 วินาที)

- **เพิ่ม:** แท็บ "เลือกโรงแรม" → **➕ เพิ่มที่พัก** กรอกแล้วกดบันทึก (คอมเมนต์ห้อง: บรรทัดละข้อ ขึ้นต้น `+` ชม, `-` ติ, `~` กลาง ๆ)
- **แก้ / ลบ:** แตะการ์ดโรงแรม → ✏️ แก้ไข หรือ 🗑 ลบ (แตะลบสองครั้งเพื่อยืนยัน) ใช้ได้กับทุกโรงแรม รวมถึง 18 แห่งเดิม
- **กู้คืน:** ⚙️ ข้อมูล → ↩️ กู้คืนโรงแรมเดิมที่ลบ
- **สำรอง:** ⚙️ ข้อมูล → คัดลอก JSON เก็บไว้ก่อนวันตัดสินใจจริง

การลบโรงแรมเดิมไม่ได้แก้ `hotels.js` แต่บันทึกว่า "ซ่อน" ไว้ในฐานข้อมูล จึงกู้คืนได้เสมอ

ที่อยู่ฐานข้อมูลตั้งไว้ที่ค่าคงที่ `DB` ต้นไฟล์ส่วน Hotels ใน `app.js`
กฎฐานข้อมูล: คัดลอกเนื้อหาไฟล์ `firebase-rules.json` ไปวางที่ Firebase → Realtime Database → Rules แล้วกด Publish (ทดสอบใน Rules Playground ก่อนได้)
กฎชุดนี้ทำ 3 อย่าง: (1) **ปิดเขียนอัตโนมัติ**เมื่อ `now` เลยเวลาที่ตั้งไว้ (ค่าเริ่มต้น `1798761600000` = 1 ม.ค. 2027 เวลา UTC เปลี่ยนเป็นมิลลิวินาทีของวันตัดสินใจจริงได้) อ่านยังได้ตามปกติ (2) ตรวจชนิดข้อมูลฝั่งเซิร์ฟเวอร์: ชื่อโรงแรมต้องเป็นข้อความไม่เกิน 120 ตัว ราคา/ขนาด/คะแนน/พิกัดต้องเป็นตัวเลข รูปต้องเป็น `data:image/jpeg|png|webp` ขนาดไม่เกิน 600KB (3) เปิดเขียนได้เฉพาะ `/hotels` และ `/photos`
หลังเลยเวลา การเพิ่ม/แก้/ลบ/อัปโหลดรูปจะแสดงข้อความว่าไม่สำเร็จ ถ้าต้องการเปิดต่อให้แก้ตัวเลขเวลาในกฎ

ใครมีลิงก์ก็แก้ได้ เหมาะกับกลุ่มที่เชื่อใจกัน ถ้าออฟไลน์จะแสดงข้อมูลล่าสุดที่เก็บไว้ในเครื่อง แต่เพิ่ม/ลบไม่ได้จนกว่าจะออนไลน์

ถ้าเคยเพิ่มที่พักไว้ด้วยเวอร์ชันเก่า (เก็บในเครื่อง) จะมีปุ่ม "อัปโหลดที่พักในเครื่องนี้" ใน ⚙️ ข้อมูล

## รูปภาพ

หน้ารายละเอียดโรงแรมมีส่วน 📷 รูปภาพ: กด **เพิ่มรูป** เลือกรูปจากเครื่อง (สูงสุด 4 รูปต่อโรงแรม) เว็บจะย่อรูปให้เหลือประมาณ 800 พิกเซลก่อนเก็บใน Firebase ที่ `/photos/<id โรงแรม>` ทุกคนเห็นตรงกัน กดรูปเพื่อขยาย กด ✕ สองครั้งเพื่อลบ
การ์ดโรงแรมที่มีรูปจะมีสัญลักษณ์ 📷

กฎของ `photos` อยู่ใน `firebase-rules.json` แล้ว

รูปที่ย่อแล้วไม่ใช่ไฟล์ต้นฉบับ ถ้าต้องการภาพความละเอียดสูงให้เก็บไว้ที่อื่นอีกชุด

## แผนที่

แท็บ **🗺️ แผนที่** แสดงโรงแรมเป็นหมุดสีตามย่าน บอกราคาต่อคืน แตะหมุดเพื่อดูสรุปและเปิดรายละเอียด ใช้ตัวกรองย่านชุดเดียวกับหน้ารายการ ใช้ OpenStreetMap และ Leaflet ฟรี ไม่ต้องมี API key

พิกัดเก็บใน Firebase ร่วมกับข้อมูลโรงแรม (ฟิลด์ `lat`, `lng`) ทุกคนเห็นตรงกัน ไม่ต้องเพิ่มกฎใหม่ มี 4 วิธีใส่พิกัด

0. **ปักอัตโนมัติ (เริ่มตรงนี้):** กดปุ่ม 🪄 ปักหมุดอัตโนมัติ เหนือแผนที่ ระบบค้นชื่อโรงแรมใน OpenStreetMap ทีละแห่ง (ราวหนึ่งวินาทีต่อแห่ง) แล้วแสดงวงกลมสีส้ม ตรวจดู แตะวงกลมที่ผิดเพื่อลบ แล้วกดยืนยันครั้งเดียว ชื่อที่ไม่พบจะยังอยู่ในรายการให้ปักเอง
1. **แตะบนแผนที่:** โรงแรมที่ยังไม่ปักอยู่ในรายการใต้แผนที่ กด 📍 ปัก แล้วแตะตำแหน่ง (หรือกด "ย้ายหมุด" ในหมุดที่ปักแล้ว)
2. **ค้นหาจากชื่อ:** กด 🔎 ค้นหา ระบบหาจาก OpenStreetMap แล้วแสดงวงกลมสีส้มให้ตรวจ ต้องแตะยืนยันตำแหน่งเอง ชื่อโรงแรมเล็ก ๆ อาจไม่เจอหรือคลาดเคลื่อน
3. **วางลิงก์ Google Maps:** ในฟอร์มแก้ไข ช่อง "ลิงก์ Google Maps" วางลิงก์เต็มที่มีพิกัด (เช่น `.../@34.65,135.50,17z...`) ระบบอ่านพิกัดให้ ลิงก์สั้น `maps.app.goo.gl` ไม่มีพิกัด ต้องเปิดแล้วคัดลอกลิงก์เต็มจากแถบที่อยู่
4. **นำเข้า JSON:** ใส่ `"lat"` และ `"lng"` ในข้อมูลที่นำเข้า ถ้าชื่อตรงกับโรงแรมที่มีอยู่ (สะกดคลาดเล็กน้อยได้) ระบบอัปเดตพิกัดให้โรงแรมนั้น ไม่สร้างซ้ำ ถ้าไม่มีชื่อนี้จึงเพิ่มเป็นโรงแรมใหม่
5. **ไฟล์ KML/KMZ จาก Google My Maps:** แปลงเป็น JSON รูปแบบ `[{"name","lat","lng"}]` (KML เก็บพิกัดเรียง ลองจิจูด,ละติจูด) แล้วนำเข้าตามข้อ 4

## แนะนำสีเสื้อผ้า

แท็บ **👗 แต่งตัว**: เลือกรูปสถานที่ (จากแกลเลอรีหรือถ่ายใหม่) ระบบดึงสีเด่นจากรูป แล้วแนะนำสีเสื้อ กางเกง/กระโปรง ถุงเท้า และรองเท้า พร้อมภาพชุดและเหตุผลของแต่ละชิ้น เลือกได้ 3 แนว: **เด่นตัดฉาก** (สีตรงข้ามกับฉาก) **กลมกลืน** (โทนเดียวกับฉาก) **ปลอดภัย** (สีกลางทั้งชุด)

มีชิป **🎨 Mood สี** 23 โทน (Warm, Cool, Soft, Powerful, Modern, Futuristic, Natural, Exclusive, Popular, Romantic, Vintage, Traditional, Dark และ Pretty, Casual, Elegant, Clear, Cool Casual, Chic, Gorgeous, Classic, Dynamic, Dandy ซึ่งตั้งชื่อตามกลุ่มบนแผนที่ Image Scale แกนอุ่น–เย็น / อ่อน–เข้ม โดยพาเลตเป็นชุดสีที่ผมกำหนดเอง ไม่ได้คัดลอกจากแผนที่) มีปุ่ม **ค้นหาเสื้อผ้าจริง** เปิด Pinterest ด้วยคำค้นภาษาอังกฤษจากสีเสื้อ/กางเกง/รองเท้าที่แนะนำ (เลือกชาย/หญิงได้) ถ้ามีรูป ชิปที่เข้ากับสีในรูปสูงสุด 3 โทนจะมี ✓ นำหน้า โทนละ 4 สี เลือกแล้วระบบจัดเสื้อ/กางเกง/ถุงเท้า/รองเท้าจากสีของโทนนั้น ใช้ได้แม้ยังไม่เลือกรูป (แก้พาเลตที่ `MOODS` ใน `style.js`)

ทำงานในเบราว์เซอร์ทั้งหมด (`style.js`) รูปไม่ถูกอัปโหลด ไม่ใช้ AI หรือ API ภายนอก คำนวณจากทฤษฎีสี ระบบดูเฉพาะ "สีในรูป" ไม่รู้จักชื่อสถานที่ และไม่คิดสีผิวหรือแสงจริงตอนถ่าย ปรับกฎสีและชื่อสีได้ที่รายการ `CH` (สีสด) และ `NE` (สีกลาง) ใน `style.js`

## หน้าตาและฟังก์ชันใหม่

ธีมครีม + เขียวเข้ม + เขียวมะนาว การ์ดไฟลท์เป็นรูปตั๋ว แถบเมนูลอยมุมมน
- **⭐ ที่ชอบ:** กดดาวที่การ์ดหรือในหน้ารายละเอียด แล้วกรองด้วยชิป "⭐ ที่ชอบ" (เก็บในเครื่องของแต่ละคน ไม่ซิงค์ข้ามเครื่อง)
- **ราคารวมทั้งทริป:** คำนวณจำนวนคืนจากเวลาบินใน `hotels.js` (ตอนนี้ 4 คืน) แสดงใต้ราคาต่อคืน และมีวันที่ดึงราคา (`priceDate` ใน `hotels.js`) กำกับ
- **ปุ่ม "ดูที่เว็บจอง":** ในหน้ารายละเอียด เปิดลิงก์ที่ใส่ไว้ ถ้าไม่มีจะค้น Google ให้

## อากาศโอซาก้า (หน้าแรก)

การ์ดอากาศสไตล์แอปสภาพอากาศของ iPhone: พื้นหลังไล่สีตามสภาพอากาศปัจจุบันและกลางวัน/กลางคืน (ฟ้าใส, เมฆ, ฝน, หิมะ) อุณหภูมิตอนนี้ตัวใหญ่ตรงกลาง สูงสุด/ต่ำสุดของวันนี้ และแผงพยากรณ์รายวันของช่วงทริปพร้อมแท่งช่วงอุณหภูมิ พร้อมคำแนะนำการแต่งตัว (แก้สีพื้นหลังที่ `SKY` ใน `app.js`) ตัวเลขอุณหภูมิใช้ฟอนต์ Sarabun น้ำหนักบาง ถ้าออฟไลน์จะใช้ฟอนต์ระบบแทน
- ถ้ายังไม่มีพยากรณ์เลย จะแสดง **ค่าเฉลี่ยหลายปี** ของต้นกุมภาพันธ์ (สูง ~9°C ต่ำ ~2°C ค่าคงที่ `NORMAL` ใน `app.js`) เพราะยังไม่มีพยากรณ์
- เมื่อวันเดินทางเข้ามาอยู่ในช่วง 16 วันข้างหน้า จะใช้ **พยากรณ์จริง** ของวันที่มี (พร้อมไอคอนอากาศ) ส่วนวันที่ยังไม่มีพยากรณ์ใช้ค่าเฉลี่ย
- ข้อมูลจาก Open-Meteo (ฟรี ไม่ต้องมี API key) ช่วงวันที่คำนวณจาก `flights` ใน `hotels.js`

## แก้ข้อมูลไฟลท์

แก้ที่ `flights` ใน `hotels.js` เวลาต้องมี timezone ครบ (ไทย `+07:00`, ญี่ปุ่น `+09:00`):
ไม่เก็บรหัสจอง (PNR) ในไฟล์ เพราะรีโพอาจเป็นสาธารณะ (ถ้าอยากโชว์ ใส่ฟิลด์ `code` เองได้)
`no` = เลขเที่ยวบินที่แสดงบนการ์ด (ถ้าว่างจะขึ้น "ยังไม่ระบุ"), `ap` = เวลาแนะนำถึงสนามบิน, `dep` = เครื่องออก, `arr` = เครื่องลง
ส่วน `depT`, `arrT`, `apT` ฯลฯ เป็นข้อความที่แสดงบนการ์ด ต้องแก้ให้ตรงกันเอง

## ข้อควรรู้

- กฎของ Firebase จะปิดเขียนเองตามเวลาที่ตั้งใน `firebase-rules.json` ถ้าไม่ต้องใช้แล้วจะลบฐานข้อมูลทิ้งก็ได้

- คอมเมนต์ห้องของโรงแรมเดิมเป็นภาษาไทยที่สรุปจากรีวิวจริงบนเว็บจองที่พัก (ดึงเมื่อ 28 ต.ค. 2026) ไม่ใช่ข้อความต้นฉบับ และยังมีโรงแรมที่ไม่มีคอมเมนต์ ให้ตรวจกับเว็บจองก่อนตัดสินใจ
- คะแนนรายหมวด (ทำเล ความสะอาด บริการ ความคุ้มค่า) ของโรงแรมเดิมมาจากไฟล์ตั้งต้น ยังไม่ได้ตรวจกับแหล่งรีวิว
- ราคาและเวลาเที่ยวบินควรเช็กกับใบยืนยันการจองอีกครั้ง
- ฟอนต์ Sarabun โหลดจาก Google Fonts ถ้าออฟไลน์จะใช้ฟอนต์ระบบแทน
